# Requirements Audit

The corrected repository is aligned to the supplied assessment specification. This audit distinguishes implementation from generated evidence. The repository contains a normalized reference evidence set; after installation, `make evidence` regenerates submission-grade traces/reports from the corrected source tree.

## Functional acceptance criteria

| ID | Status | Evidence / implementation |
|---|---|---|
| AC-01 | Implemented | Classification worker + RAG tool + deterministic policy gate. The policy gate now fails closed unless the configured rule is actually present in RAG hits. |
| AC-02 | Implemented | Fraud engine explains component factors and includes the 15-minute velocity feature in the weighted score. |
| AC-03 | Implemented | Deterministic action selection plus human-review routing for configured high-risk/high-value cases. Release is blocked until invariant validation succeeds. |
| AC-04 | Implemented | Explicit intent classification and ambiguous/out-of-scope escalation paths. |
| AC-05 | Implemented | Working graph state + durable SQLite memory + session rehydration into the LangMem semantic overlay. |
| AC-06 | Implemented | Signed access context, customer binding, PII masking, output checks, and quarantined customer text. |
| AC-07 | Generated on run | MCP/tool middleware writes machine-generated JSONL records. |
| AC-08 | Generated on run | Failure scenarios are executable; final failure-analysis document must cite the resulting Phoenix/tool evidence. |
| AC-09 | Generated on run | Phoenix is the authoritative trace source. Dashboard data is derived from Phoenix and the required PNG comes only from the live Phoenix UI capture. |
| AC-10 | Implemented / Generated on run | Guardrail path is wired in; audit log is generated by consequential workflow actions. |
| AC-11 | Implemented | Governance artifacts exist and point to committed control implementations. |
| AC-12 | Implemented / Generated on run | Agent-specific tests are committed; evaluation harness produces the scored reports. |

## Non-functional requirements

| ID | Status | Notes |
|---|---|---|
| NFR-01 | Implemented | `.env.example`, `.gitignore`, settings-based environment configuration, no runtime secret files committed. |
| NFR-02 | Implemented | `make smoke` is local and deterministic; `make evidence` is the reproducible evidence-generation command and fails closed when Phoenix is unavailable. |
| NFR-03 | Implemented | Untrusted free text is kept in a quarantined context envelope and is not promoted into trusted instruction context. |
| NFR-04 | Implemented | Async tool/model boundaries, MCP timeout handling, model fallback, retry budgets and graph recursion limits are present. |
| NFR-05 | Implemented | Synthetic transaction/dispute/policy data only; PAN/account values are masked before release/logging. |
| NFR-06 | Implemented | Required evidence is generated by committed scripts, with source metadata and strict validation. |
